# 010.VISUALIZATION.md

이 문서는 [Application Architecture](../001.model/007.APPLICATION_ARCHITECTURE.md#visualization)의 Visualization을 구현하는 방안을 정합니다. Visualization의 역할은 model 문서를 따르며, 이 문서는 바꾸지 않습니다. 결정 배경은 [Choose the implementation tooling and Visualization stack](../../adr/2026-10-30-choose-the-implementation-tooling-and-visualization-stack.md)을 참고하세요. 용어는 [Glossary](../001.model/002.GLOSSARY.md)를 따릅니다.

## 구성

Visualization은 브라우저에서 실행되는 SPA와, 이 SPA에 데이터를 주는 Hono 라우트로 이루어집니다.

- SPA는 Preact로 만듭니다. Hono 라우트는 Core의 Query API를 불러 JSON으로 돌려주며, Persistence에 직접 접근하지 않습니다.
- 서버 렌더링은 하지 않습니다. Daemon과 Main Server가 이벤트 루프를 함께 쓰므로, 큰 input의 화면을 서버에서 만들면 수집이 멈춥니다.
- SPA는 빌드할 때 Bun 매크로로 번들해 실행 파일에 문자열로 넣습니다. HTML과 번들도 Hono 라우트가 내줍니다. `Bun.serve`의 `routes`로 내주면 Hono의 접근 검사를 거치지 않아서, 아래 [접속](#접속)의 규칙을 지킬 수 없기 때문입니다.
- 스타일은 일반 CSS로 씁니다. 토큰 차트는 SVG로 직접 그립니다.

## 접속

Main Server의 데이터에는 프롬프트와 Tool Call 결과의 원문이 있습니다. 같은 머신의 다른 계정도 localhost의 포트에 연결할 수 있으므로, 바인딩만으로는 이 데이터를 보호할 수 없습니다.

- `127.0.0.1`에만 바인딩합니다.
- 포트는 설정할 수 있고, 기본값은 `0`입니다. 운영체제가 빈 포트를 고르므로 계정마다 Daemon이 상주해도 충돌하지 않습니다.
- Main Server는 시작할 때 접근 토큰(난수 32바이트의 base64url)을 만들고, 주소와 토큰을 상태 디렉터리의 권한 `0600` 파일 `visualization.json`에 씁니다. `alm url` 명령이 이 파일을 읽어 접속 URL을 출력합니다.
- 브라우저가 URL의 토큰으로 처음 접속하면 Main Server는 `HttpOnly`, `SameSite=Strict` 쿠키를 주고 토큰이 없는 URL로 보냅니다.
- 쿠키나 토큰이 없는 요청은 `401`로 거절합니다. `Host` 헤더가 바인딩한 주소와 다른 요청도 거절해 DNS rebinding을 막습니다.

| 항목 | 설명 |
|---|---|
| Visualization 포트 | 기본값은 `0`입니다. |

## 큰 데이터 조회

Session Log Event 본문은 수백 KB에 이를 수 있습니다. 여러 본문을 메모리에 모으면 수집과 함께 쓰는 프로세스의 메모리가 오릅니다.

- LLM Call 목록은 메타데이터만 돌려줍니다. 본문은 사용자가 펼칠 때 요청합니다.
- 본문은 `bun:sqlite`의 `.iterate()`로 한 행씩 읽어 스트리밍 응답으로 보냅니다. `.all()`로 모으거나 여러 본문을 한 번에 `JSON.stringify`하지 않습니다.
- LLM Call의 input은 Session Log Event 하나를 한 줄로 담은 NDJSON(`application/x-ndjson`)으로 보냅니다. 브라우저는 받는 대로 한 줄씩 표시하고, 내용은 사용자가 펼칠 때 보여 줍니다.

## 화면

| 화면 | 내용 |
|---|---|
| Session 목록 | 시작 시각순. 에이전트 id와 `cwd`로 거릅니다. 첫 프롬프트, Agent 수, Turn 수, `completed`가 아닌 Turn 수, Token 합계를 보여 줍니다. |
| Session | Agent 트리와 선택한 Agent의 Turn 목록(`status`, 프롬프트, Loop 수, Tool Call 수, 오류 수, Duration, Token 합계)입니다. Session을 지울 수 있습니다. |
| Turn | 프롬프트, Loop와 Compaction별 Token Usage 차트, 그리고 Turn 안 위치 순서의 Loop와 Compaction입니다. |
| Loop | 모델, Stop Reason, Duration, Token Usage, LLM 호출 오류와 Tool Call입니다. output과 input, Tool Call의 인자와 결과는 펼칠 때 불러옵니다. Subagent를 띄운 Tool Call에서 그 Subagent로 갈 수 있습니다. |

## 결정되지 않은 사항

- 잘못된 판단 지점과 토큰 낭비를 찾기 위해 보여 줄 화면([Application Architecture](../001.model/007.APPLICATION_ARCHITECTURE.md#결정되지-않은-사항) 참고). 위 [화면](#화면)은 역추적에 필요한 최소한이며, 낭비를 판단하는 기준은 넣지 않았습니다.
