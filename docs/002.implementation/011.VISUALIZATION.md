# 011.VISUALIZATION.md

이 문서는 [Application Architecture](../001.model/007.APPLICATION_ARCHITECTURE.md#visualization)의 Visualization을 구현하는 방안을 정합니다. Visualization의 역할은 model 문서를 따르며, 이 문서는 바꾸지 않습니다. 결정 배경은 [Choose the implementation tooling and Visualization stack](../../adr/2026-10-30-choose-the-implementation-tooling-and-visualization-stack.md)을 참고하세요. Visualization이 쓰는 Query API는 [Query API](010.QUERY_API.md)를 참고하세요. 용어는 [Glossary](../001.model/002.GLOSSARY.md)를 따릅니다.

## 구성

Visualization은 브라우저에서 실행되는 SPA와, 이 SPA에 데이터를 주는 Hono 라우트로 이루어집니다.

- Main Server가 웹 서버 역할을 합니다. Visualization 페이지(SPA의 HTML, JavaScript, CSS)와 SPA가 읽는 데이터(JSON)를 모두 Main Server가 제공하며, 따로 웹 서버를 띄우지 않습니다.
- Main Server 프로세스의 `Bun.serve` 하나가 `routes`로 SPA를, `fetch`로 Hono 라우트를 함께 제공합니다. Main Server가 시작할 때 함께 시작하고, 종료할 때 함께 멈춥니다.
- SPA는 Preact로 만듭니다. Hono 라우트는 Core의 Query API를 [프로세스 내 호출](010.QUERY_API.md#호출-방식)로 불러 JSON으로 돌려주며, Persistence에 직접 접근하지 않습니다.
- 서버 렌더링은 하지 않습니다. Daemon과 Main Server가 이벤트 루프를 함께 쓰므로, 큰 input의 화면을 서버에서 만들면 수집이 멈춥니다.
- SPA는 Bun으로 번들해 실행 파일에 넣습니다.
- `visualization` 패키지가 SPA와 Hono 라우트를 담고, `app`이 Query API를 넘겨 `Bun.serve`에 붙입니다([패키지 구성](001.TECH_STACK.md#패키지-구성) 참고).
- 스타일은 일반 CSS로 씁니다. 토큰 차트는 SVG로 직접 그립니다.
- SPA는 페이지 하나이며 `/`로 제공합니다. 화면은 URL의 hash로 고릅니다. `#/`는 Session 목록, `#/session/<에이전트 id>/<Session ID>`는 Session Graph이며, 식별자는 URL 인코딩합니다. 서버의 경로를 하나만 두면 `routes`에 SPA를 하나만 붙이면 됩니다.

## 구현 범위

처음 구현하는 범위입니다. [Visualization](../001.model/009.VISUALIZATION.md)의 나머지 화면 요소는 필요한 질의를 Query API에 더한 뒤에 구현합니다([Query API의 결정되지 않은 사항](010.QUERY_API.md#결정되지-않은-사항) 참고).

| 화면 | 처음 구현하는 것 |
|---|---|
| Session 목록 | 시작 시각순 정렬, 에이전트 id, 작업 디렉터리, 머신으로 거르기, 이어 보기. 마지막 활동 시각순과 Token 합계순 정렬, Session마다의 수와 Signal은 뒤로 미룹니다. |
| Session Graph | Turn 단위로 불러온 Node 메타데이터(`getTurnNodes`)로 그리는 Lane, Node, Edge와 Token 열. 접힌 Turn은 Turn 목록(`listTurns`)의 요약만으로 그립니다. |
| Tooltip | 프롬프트와 Tool Call 인자의 앞부분은 Node 메타데이터에 든 것을 씁니다. |
| Detail Panel | Tool Call의 인자와 결과, LLM Call의 전체 input과 output, 프롬프트, Compaction의 요약 |

## 라우트

Hono 라우트는 Query API의 메서드 하나를 불러 그 결과를 JSON으로 돌려줍니다. 경로의 식별자는 URL 인코딩한 경로 조각 하나로 넣습니다. Session ID와 Agent ID에 `/`가 들어 있을 수 있기 때문입니다.

| 라우트 | Query API |
|---|---|
| `GET /api/sessions?agent=&cwd=&host=&limit=&offset=` | `listSessions` |
| `GET /api/sessions/:agentKind/:sessionId` | `getSession` |
| `GET /api/sessions/:agentKind/:sessionId/agents/:agentId/turns` | `listTurns` |
| `GET /api/sessions/:agentKind/:sessionId/agents/:agentId/turns/:turnId/nodes` | `getTurnNodes` |
| `GET /api/sessions/:agentKind/:sessionId/agents/:agentId/llm-calls/:llmCallId/input` | `iterateLlmCallInput`. [큰 데이터 조회](#큰-데이터-조회)대로 NDJSON으로 스트리밍합니다. |
| `GET /api/sessions/:agentKind/:sessionId/agents/:agentId/llm-calls/:llmCallId/tool-calls/:ordinal` | `getToolCall` |
| `GET /api/sessions/:agentKind/:sessionId/events/:eventId` | `getEventBody`. 원문을 그대로 돌려줍니다. |

- Query API가 `undefined`를 돌려주면 `404`로 답합니다.
- 모든 라우트는 [접속](#접속)의 인증을 거칩니다.
- `/api/sessions`의 `limit`은 기본값이 `50`입니다. `limit`과 `offset`이 음이 아닌 정수가 아니거나 `limit`이 `0`이면 `400`으로 답합니다. `500`보다 큰 `limit`은 Query API가 `500`으로 줄입니다.
- 응답에는 `Cache-Control: no-store`를 붙여 브라우저가 원문을 디스크에 남기지 않게 합니다.

## 접속

Main Server의 데이터에는 프롬프트와 Tool Call 결과의 원문이 있습니다. 같은 머신의 다른 계정도 localhost의 포트에 연결할 수 있으므로, 바인딩만으로는 이 데이터를 보호할 수 없습니다.

- `127.0.0.1`에만 바인딩합니다.
- 포트는 설정할 수 있고, 기본값은 `0`입니다. 운영체제가 빈 포트를 고르므로 계정마다 Daemon이 상주해도 충돌하지 않습니다.
- Main Server는 시작할 때 접근 토큰을 만들고, 주소와 토큰을 상태 디렉터리의 권한 `0600` 파일에 씁니다. 실행 파일의 명령이 이 파일을 읽어 접속 URL을 출력합니다.
- 브라우저가 URL의 토큰으로 처음 접속하면 Main Server는 `HttpOnly`, `SameSite=Strict` 쿠키를 주고 토큰이 없는 URL로 보냅니다.
- 쿠키나 토큰이 없는 요청은 `401`로 거절합니다. `Host` 헤더가 바인딩한 주소와 다른 요청도 거절해 DNS rebinding을 막습니다.

| 항목 | 키 | 기본값 | 설명 |
|---|---|---|---|
| Visualization 포트 | `port` | `0` | 설정 파일([Client Adapter Daemon 구현](007.CLIENT_ADAPTER_DAEMON.md#설정))의 `[visualization]` 표에 둡니다. `0`부터 `65535`까지입니다. |

### 접속 정보 파일과 토큰

- 접속 정보 파일은 Daemon의 상태 디렉터리([Client Adapter Daemon 구현](007.CLIENT_ADAPTER_DAEMON.md#설정))의 `visualization.json`입니다. 상태 디렉터리는 계정마다 하나이고 Daemon의 잠금 파일이 지키므로, Daemon이 잠금을 얻은 뒤에 Visualization을 시작합니다. 같은 상태 디렉터리로 두 번째 프로세스를 띄워도 실행 중인 프로세스의 파일을 덮어쓰지 않습니다.
- 내용은 JSON 객체 하나입니다: `{"url": "http://127.0.0.1:<포트>/", "token": "<접근 토큰>", "pid": <프로세스 id>}`. 다 쓴 임시 파일의 이름을 바꾸어 만들므로 읽는 쪽이 반쯤 쓴 파일을 보지 않습니다. 종료할 때 지웁니다.
- 접근 토큰은 시작할 때마다 만드는 32바이트 난수를 base64url로 쓴 43자입니다. 다시 시작하면 이전 쿠키는 쓸 수 없습니다.
- `agentoscope url [--config <경로>]`는 이 파일을 읽어 `http://127.0.0.1:<포트>/login?token=<토큰>`을 출력합니다. 파일이 없으면 실행 중이 아니라고 알리고 종료 코드 `1`로 끝납니다. Main Server의 로그에는 토큰을 빼고 주소만 남깁니다.
- `GET /login?token=`이 토큰을 확인해 쿠키를 주고 `303`으로 `/`에 보냅니다. 토큰은 고정 시간에 비교합니다.
- SPA의 페이지(`/`)와 그 JavaScript, CSS는 데이터를 담지 않으므로 인증 없이 제공합니다. 데이터는 모두 `/api/` 아래의 라우트로 읽고, 이 라우트가 인증과 `Host` 헤더를 확인합니다. 쿠키가 없어 `401`을 받으면 SPA는 `agentoscope url`을 실행하라고 안내합니다.
- Visualization을 시작하지 못하면(예: 포트를 쓸 수 없음) 오류 로그를 남기고 수집은 계속합니다.

## 큰 데이터 조회

Session Log Event 본문은 수백 KB에 이를 수 있습니다. 여러 본문을 메모리에 모으면 수집과 함께 쓰는 프로세스의 메모리가 오릅니다.

- LLM Call 목록은 메타데이터만 돌려줍니다. 본문은 사용자가 펼칠 때 요청합니다.
- 본문은 `bun:sqlite`의 `.iterate()`로 한 행씩 읽어 스트리밍 응답으로 보냅니다. `.all()`로 모으거나 여러 본문을 한 번에 `JSON.stringify`하지 않습니다.
- LLM Call의 input은 NDJSON(`application/x-ndjson`)으로 보냅니다. 한 줄이 Session Log Event 하나이며, `eventId`, `turnId`, `position`, `type`, `timestampUs`, 원문의 길이(문자 수) `size`와 원문 `body`를 담습니다. 저장된 원문은 JSON이므로 다시 직렬화하지 않고 그대로 붙입니다. 브라우저가 다음 줄을 읽을 때 다음 행을 읽으며, 연결을 끊으면 읽기를 닫습니다.
- Detail Panel은 원문을 앞 20,000자까지 보이고, 누르면 전체를 보입니다. LLM Call의 input은 사용자가 펼칠 때 읽습니다.

## 결정되지 않은 사항

- 잘못된 판단 지점과 토큰 낭비를 찾기 위해 보여 줄 화면([Application Architecture](../001.model/007.APPLICATION_ARCHITECTURE.md#결정되지-않은-사항) 참고)
- 큰 본문을 브라우저에서 표시하는 방법. 지금은 앞 20,000자까지 보이고 누르면 전체를 보입니다.
