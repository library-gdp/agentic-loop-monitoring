# 010.QUERY_API.md

이 문서는 [Application Architecture](../001.model/007.APPLICATION_ARCHITECTURE.md#core)의 Query API를 구현하는 방안을 정합니다. Query API가 답하는 질의는 [Data Architecture의 읽기](../001.model/008.DATA_ARCHITECTURE.md#읽기)와 [Visualization의 더해야 하는 질의](../001.model/009.VISUALIZATION.md#더해야-하는-질의)를 따르며, 이 문서는 바꾸지 않습니다. 저장소에서 읽는 방법은 [Data Storage](008.DATA_STORAGE.md#읽기)를, Visualization이 Query API를 쓰는 방법은 [Visualization 구현](011.VISUALIZATION.md)을 참고하세요. 용어는 [Glossary](../001.model/002.GLOSSARY.md)를 따릅니다.

## 호출 방식

Query API는 프로세스 내 호출로 구현합니다. Visualization은 같은 프로세스에서 Query API의 메서드를 직접 부릅니다.

- `core` 패키지가 `QueryApi` 인터페이스와, Repository API의 구현을 받아 `QueryApi`를 만드는 `createQueryApi(repository)`를 내보냅니다.
- `app`이 `createQueryApi`로 만든 객체를 Visualization에 넘깁니다. Visualization은 `QueryApi` 타입에만 의존하고 Persistence를 알지 못합니다.
- 인자와 반환값은 TypeScript 객체 그대로 주고받습니다. 직렬화하지 않고, 네트워크를 거치지 않습니다.
- 메서드는 동기입니다. Persistence가 쓰는 `bun:sqlite`가 동기 API이기 때문입니다([Data Storage](008.DATA_STORAGE.md#저장소) 참고).
- 찾는 대상이 없으면 `undefined`를 돌려줍니다.
- 시각은 UTC Unix epoch 마이크로초이며, 필드 이름이 `...Us`로 끝납니다.
- 다른 프로세스에서 Query API를 부르는 방식(예: HTTP)은 두지 않습니다. 브라우저와 Main Server 사이의 HTTP는 Visualization 안의 일입니다([Visualization 구현](011.VISUALIZATION.md#라우트) 참고).

## 메서드

| 메서드 | 돌려주는 것 | 답하는 질의 |
|---|---|---|
| `listSessions(filter)` | Session 목록. [시작 시각순](#session-목록)입니다. | Session 목록 |
| `getSession(ref)` | Session과 그 Agent 트리 | Session의 Agent 트리 |
| `listTurns(ref)` | Agent의 Turn 목록. Turn 순서를 따르며, 프롬프트의 앞부분과 Token Usage 합계를 담습니다. | Agent의 Turn 목록 |
| `getTurn(ref)` | Turn의 Loop, LLM Call, Tool Call, Compaction과 프롬프트 전체 | Turn의 Loop, LLM Call, Tool Call, Compaction |
| `getTurnNodes(ref)` | Turn의 Node 메타데이터. [Turn의 Node 메타데이터](#turn의-node-메타데이터)를 참고하세요. | Turn의 Node 메타데이터 |
| `listLlmCalls(ref, filter)` | Session의 LLM Call. Agent, 오류, Stop Reason으로 거릅니다. | 오류로 끝난 LLM Call과 재시도, Stop Reason별 LLM Call |
| `getToolCall(ref)` | Tool Call과 그 인자, 결과 전체 | Tool Call의 인자와 결과 |
| `iterateLlmCallInput(ref)` | LLM Call의 input에 든 Session Log Event를 하나씩 돌려주는 `Iterable` | LLM Call의 input |
| `getEventBody(ref)` | Session Log Event 하나의 JSON 원문 | LLM Call의 output, Tool Call의 결과, Compaction의 요약, 프롬프트 |

- `iterateLlmCallInput`이 돌려준 `Iterable`은 끝까지 읽거나 `return()`을 불러 닫아야 합니다. 읽는 동안 읽기 전용 연결 하나를 씁니다([Data Storage](008.DATA_STORAGE.md#읽기) 참고).
- `getTurn`과 `getTurnNodes`는 같은 Turn을 다르게 돌려줍니다. `getTurn`은 Loop 단위로 묶고 프롬프트 전체를 담으며, `getTurnNodes`는 Session Graph에 그릴 Node를 Turn 안 위치 순으로 늘어놓고 원문은 앞부분만 담습니다.

## Session 목록

`listSessions`는 지금 시작 시각순만 지원합니다.

- 시작 시각이 늦은 Session이 앞입니다. 시작 시각은 그 Session의 Turn의 `started_at` 가운데 가장 이른 것이며, Turn이 없는 Session은 처음 받은 시각으로 정렬합니다([Data Storage](008.DATA_STORAGE.md#읽기) 참고).
- 에이전트 id, 작업 디렉터리, 머신으로 거르고, `limit`와 `offset`으로 나누어 불러옵니다. `limit`은 1부터 500까지입니다.
- [Visualization](../001.model/009.VISUALIZATION.md#session-목록)의 기본 정렬인 마지막 활동 시각순과 Token 합계순, Session마다의 수와 Signal 수는 아직 지원하지 않습니다([결정되지 않은 사항](#결정되지-않은-사항)).

## Turn의 Node 메타데이터

`getTurnNodes`는 Turn 하나의 [Node](../001.model/009.VISUALIZATION.md#node) 메타데이터를 돌려줍니다. Session Graph는 이 메서드로 Turn 단위로 나누어 불러옵니다.

```ts
interface QueryApi {
    /** Turn의 Node 메타데이터입니다. Turn 안 위치 순이며, 원문은 앞부분만 담습니다. */
    getTurnNodes(ref: TurnRef): TurnNodes | undefined;
}

/** Turn 하나의 Node입니다. TurnSummary의 promptPreview와 promptLength가 Prompt Node의 앞부분과 길이입니다. */
interface TurnNodes extends TurnSummary {
    /** Turn 안 위치 순입니다. Tool Call은 요청한 LLM Call Node의 toolCalls에 있습니다. */
    readonly nodes: readonly TurnNode[];
}

type TurnNode = PromptNode | LlmCallNode | CompactionNode | InterruptNode | GapNode;

/** Turn을 시작한 user_message입니다. 언제나 nodes의 첫 Node입니다. */
interface PromptNode {
    readonly kind: "prompt";
    readonly position: 0;
    readonly timestampUs: number;
}

interface LlmCallNode {
    readonly kind: "llm_call";
    /** assistant_message의 Turn 안 위치입니다. */
    readonly position: number;
    readonly llmCall: LlmCall;
    /** 이 LLM Call이 요청한 Tool Call입니다. ordinal 순입니다. */
    readonly toolCalls: readonly ToolCallNode[];
}

interface ToolCallNode extends ToolCall {
    /** tool_use 블록의 input을 JSON 텍스트로 쓴 것의 앞부분입니다. */
    readonly inputPreview: string;
    /** inputPreview를 자르기 전 JSON 텍스트의 길이(문자 수)입니다. */
    readonly inputLength: number;
    /** tool_result의 output의 길이(문자 수)입니다. 결과가 기록되지 않았으면 비웁니다. */
    readonly resultLength?: number;
}

interface CompactionNode {
    readonly kind: "compaction";
    /** compaction의 Turn 안 위치입니다. */
    readonly position: number;
    readonly compaction: Compaction;
}

/** turn_interrupted입니다. 중단된 Turn의 마지막 Node입니다. */
interface InterruptNode {
    readonly kind: "interrupt";
    readonly position: number;
    readonly eventId: string;
    readonly timestampUs: number;
}

/** 저장된 Session Log Event가 없는 Turn 안 위치가 이어진 자리입니다. */
interface GapNode {
    readonly kind: "gap";
    /** 비어 있는 첫 Turn 안 위치입니다. */
    readonly position: number;
    /** 비어 있는 위치의 수입니다. */
    readonly count: number;
}
```

`TurnRef`, `TurnSummary`, `LlmCall`, `ToolCall`, `Compaction`은 `core`의 기존 타입입니다.

### 구성 규칙

- Turn의 행이 없으면(Turn 안 위치 `0`에 Turn을 시작한 `user_message`가 없으면) `undefined`를 돌려줍니다.
- `nodes`는 Turn 안 위치 순입니다. LLM Call, Compaction, Interrupt Node는 각각 `assistant_message`, `compaction`, `turn_interrupted`의 Turn 안 위치에 놓습니다.
- Tool Call은 따로 Node를 두지 않고 요청한 LLM Call Node의 `toolCalls`에 담습니다. Tool Call의 결과(`tool_result`)와 Compaction의 요약(`compaction_summary`)도 Node가 아닙니다.
- Turn 안 위치는 Turn을 시작한 `user_message`의 `0`부터 하나씩 늘어나므로([Agent Logging Protocol](../001.model/004.AGENT_LOGGING_PROTOCOL.md#transport-unit)), `0`부터 그 Turn에 저장된 가장 큰 위치까지에서 비어 있는 위치가 이어진 자리마다 Gap Node를 하나 둡니다. 마지막 위치 뒤에 빠진 기록은 알 수 없습니다.
- Core가 모르는 `type`의 Session Log Event와, 위의 어느 Node도 만들지 않는 Session Log Event(예: Turn 중간의 `user_message`)는 Node를 만들지 않습니다. 이 위치는 비어 있지 않으므로 Gap Node도 만들지 않습니다. [Context Node](../001.model/009.VISUALIZATION.md#node)는 아직 만들지 않습니다(Visualization의 빠진 데이터 D2, D3).
- 원문은 담지 않습니다. 다만 프롬프트의 앞부분(`promptPreview`)과 Tool Call 인자의 앞부분(`inputPreview`)은 [앞부분 읽기](#앞부분-읽기)대로 원문에서 읽어 담습니다.

### Session Graph를 불러오는 순서

1. `getSession`으로 Agent 트리를 읽습니다.
2. Agent마다 `listTurns`로 Turn 목록을 읽습니다. 접힌 Turn은 여기서 읽은 `TurnSummary`(`status`, 수, Token 합계, 프롬프트의 앞부분)만으로 그립니다.
3. 펼친 Turn마다 `getTurnNodes`를 부릅니다. Subagent의 Turn은 Spawn한 Tool Call(`subagentId`)이나 Subagent의 Lane을 펼칠 때 부릅니다.
4. Tooltip과 Detail Panel의 원문은 `getToolCall`, `getEventBody`, `iterateLlmCallInput`으로 읽습니다.

## 앞부분 읽기

프롬프트와 Tool Call 인자의 앞부분은 파생 데이터에 두지 않고, 질의할 때 원본 데이터인 Session Log Event의 원문에서 읽습니다.

- 앞부분의 길이는 200자입니다(`PROMPT_PREVIEW_LENGTH`). [Tooltip](../001.model/009.VISUALIZATION.md#tooltip)이 보이는 길이와 같으므로, 프롬프트와 Tool Call의 Tooltip은 Query API를 다시 부르지 않고 그릴 수 있습니다.
- Persistence가 SQLite의 JSON 함수로 앞부분과 전체 길이만 꺼내 Core에 넘깁니다. 원문 전체를 JavaScript의 메모리로 옮기지 않습니다([Data Storage](008.DATA_STORAGE.md#읽기) 참고).
- 파생 데이터에 두지 않으므로 앞부분의 길이를 바꾸어도 파생 데이터를 다시 만들지 않습니다. 대신 질의할 때 SQLite가 원문을 읽으므로, Turn 하나에 큰 `assistant_message`가 많으면 `getTurnNodes`가 느려질 수 있습니다.

## 결정되지 않은 사항

- `listSessions`의 마지막 활동 시각순과 Token 합계순 정렬, Session마다의 수와 Signal 수
- [Visualization의 더해야 하는 질의](../001.model/009.VISUALIZATION.md#더해야-하는-질의) 가운데 아직 없는 것: LLM Call의 output과 Compaction 요약의 앞부분(Node 미리보기), Input Delta, Subagent까지 더한 Token 합계, Session의 Signal 목록
- 다른 프로세스에서 Query API를 부르는 방식
