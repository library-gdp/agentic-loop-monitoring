# 007.CLIENT_ADAPTER_DAEMON.md

이 문서는 [Client Adapter Daemon](../001.model/006.CLIENT_ADAPTER_DAEMON.md)(이하 Daemon)을 구현하는 방안을 정합니다. Daemon의 동작과 규칙은 model 문서를 따르며, 이 문서는 바꾸지 않습니다. 구현 언어는 [Tech Stack](001.TECH_STACK.md)을, Plugin의 구현은 [Plugin Guide](004.PLUGIN_GUIDE.md)를 참고하세요. 용어는 [Glossary](../001.model/002.GLOSSARY.md)를 따릅니다.

## 실행

Daemon은 에이전트를 실행하는 사용자 계정마다 하나씩 상주합니다. 에이전트는 Session Log를 보통 사용자의 홈 디렉터리 아래에 파일로 기록하므로, Daemon은 그 사용자의 권한으로 실행합니다.

- Daemon은 Main Server와 한 프로세스로 Bun에서 실행됩니다. 실행 파일은 `bun build --compile`로 만든 하나입니다([Tech Stack](001.TECH_STACK.md#실행-구성) 참고). 빌드할 때 `--no-compile-autoload-dotenv`와 `--no-compile-autoload-bunfig`를 넣습니다. 넣지 않으면 실행한 디렉터리의 `.env`와 `bunfig.toml`을 읽습니다.
- Plugin은 실행 파일에 들어 있지 않습니다. Daemon은 실행 파일 밖의 Plugin 디렉터리에 있는 ES 모듈을 동적 `import()`로 불러옵니다. `--compile`의 기본 옵션으로 동작합니다.
- 같은 상태 디렉터리를 쓰는 다른 Daemon이 이미 실행 중이면 시작하지 않고 종료합니다.

## 상주

실행 파일의 서비스 등록 명령이 플랫폼에 맞는 서비스 파일을 만듭니다.

| 플랫폼 | 방식 | 설정 |
|---|---|---|
| Linux | systemd user service | 실패하면 다시 시작합니다. `MemoryMax`로 메모리 상한을 겁니다. 값은 `256M`입니다. 측정한 RSS(대기 약 33 MB, 조회 뒤 약 38 MB)에 대기열과 큰 input 조회를 위한 여유를 더했습니다. |
| macOS | launchd | 실패하면 다시 시작합니다. |

`alm service install`은 서비스 파일만 만듭니다. 서비스를 켜는 일(`systemctl --user enable --now agentic-loop-monitoring`, `launchctl load`)은 사용자가 합니다.

## 배포

GitHub Releases에 플랫폼별 실행 파일, Plugin `.js`, SHA-256 체크섬을 올립니다. 지원 플랫폼은 [Tech Stack](001.TECH_STACK.md#지원-플랫폼과-배포)을 참고하세요.

## 설정

설정 파일은 TOML이며 `Bun.TOML.parse`로 읽습니다. [Client Adapter Daemon의 설정](../001.model/006.CLIENT_ADAPTER_DAEMON.md#설정)에 더해 다음 항목을 둡니다.

| 항목 | 설명 |
|---|---|
| 상태 디렉터리 | Daemon 로그 등 Daemon이 쓰는 파일을 두는 디렉터리입니다. Plugin의 상태는 그 아래 `plugins/<에이전트 id>`에 둡니다. |
| Plugin 디렉터리 | 빌드한 Plugin을 두는 디렉터리입니다. Daemon은 시작할 때 여기 있는 Plugin을 모두 불러와 Plugin Collection에 등록하고, 그 가운데 "사용할 Plugin"을 시작합니다([Plugin Guide](004.PLUGIN_GUIDE.md#daemon이-plugin을-불러오는-방식) 참고). |
| Transport | 기본값은 [프로세스 내 호출](003.TRANSPORT.md#프로세스-내-호출)입니다. 표준입출력이면 실행할 Main Server 명령입니다. Transport별 주소는 [Transport](003.TRANSPORT.md#transport-바인딩)를 참고하세요. |
| 역할 | 기본값 `all`은 Daemon과 Main Server를 한 프로세스로 실행합니다. `daemon`과 `server`는 [REST API](003.TRANSPORT.md#rest-api) Transport로 나누어 실행합니다. |
| Plugin별 값 | `[plugins.<에이전트 id>]`입니다. Plugin의 `options`로 넘깁니다. |

### 기본값

| 항목 | 설정 파일의 키 | 기본값 |
|---|---|---|
| 설정 파일 | (`--config`) | `$XDG_CONFIG_HOME/agentic-loop-monitoring/config.toml`. 없으면 모두 기본값으로 실행합니다. |
| 역할 | `role` | `all` |
| 상태 디렉터리 | `state_directory` | `$XDG_STATE_HOME/agentic-loop-monitoring` |
| Plugin 디렉터리 | `plugin_directory` | `$XDG_DATA_HOME/agentic-loop-monitoring/plugins` |
| 사용할 Plugin | `enabled_plugins` | `["opencode"]` |
| Transport | `transport.kind`, `transport.base_url` | `in-process` |
| Ack 타임아웃 | `transport.ack_timeout_ms` | 10초 |
| 재시도 횟수 | `transport.retry_count` | 5회 |
| 재시도 간격 | `transport.retry_interval_ms` | 0.5초에서 시작해 재시도마다 두 배 |

`$XDG_CONFIG_HOME`, `$XDG_STATE_HOME`, `$XDG_DATA_HOME`의 기본값은 각각 `~/.config`, `~/.local/state`, `~/.local/share`이며, macOS에서도 같습니다.

### 구현한 Transport

구현한 Transport는 프로세스 내 호출과 REST API입니다. `transport.kind`는 `in-process`, `rest`만 받습니다. 표준입출력, Unix Socket, Streamable HTTP, WebSocket은 아직 구현하지 않았습니다.

### 종료

종료 신호를 받으면 Plugin을 멈추고, 전송 대기열을 최대 5초 동안 비운 뒤 끝냅니다. 그때까지 보내지 못한 Transport Unit은 로그를 남기고 버립니다. Plugin의 `stop`도 최대 5초를 기다립니다.

## 결정되지 않은 사항

- 전송 대기열의 크기 상한([Plugin Interface](005.PLUGIN_INTERFACE.md#결정되지-않은-사항) 참고). 지금은 상한이 없습니다. Plugin은 읽기 묶음마다 이벤트 루프를 양보합니다.
