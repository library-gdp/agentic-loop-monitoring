# 007.CLIENT_ADAPTER_DAEMON.md

이 문서는 [Client Adapter Daemon](../001.model/006.CLIENT_ADAPTER_DAEMON.md)(이하 Daemon)을 구현하는 방안을 정합니다. Daemon의 동작과 규칙은 model 문서를 따르며, 이 문서는 바꾸지 않습니다. 구현 언어는 [Tech Stack](001.TECH_STACK.md)을, Plugin의 구현은 [Plugin Guide](004.PLUGIN_GUIDE.md)를 참고하세요. 용어는 [Glossary](../001.model/002.GLOSSARY.md)를 따릅니다.

## 실행

Daemon은 에이전트를 실행하는 사용자 계정마다 하나씩 상주합니다. 에이전트는 Session Log를 보통 사용자의 홈 디렉터리 아래에 파일로 기록하므로, Daemon은 그 사용자의 권한으로 실행합니다.

- Daemon은 Main Server와 한 프로세스로 Bun에서 실행됩니다. 실행 파일은 `bun build --compile`로 만든 하나입니다([Tech Stack](001.TECH_STACK.md#실행-구성) 참고). 빌드할 때 `--no-compile-autoload-dotenv`와 `--no-compile-autoload-bunfig`를 넣습니다. 넣지 않으면 실행한 디렉터리의 `.env`와 `bunfig.toml`을 읽습니다.
- Plugin은 실행 파일에 들어 있지 않습니다. Daemon은 실행 파일 밖의 Plugin 디렉터리에 있는 ES 모듈을 동적 `import()`로 불러옵니다. `--compile`의 기본 옵션으로 동작합니다.
- 같은 상태 디렉터리를 쓰는 다른 Daemon이 이미 실행 중이면 시작하지 않고 종료합니다.

## 상주

실행 파일의 서비스 등록 명령이 플랫폼에 맞는 서비스 파일을 만듭니다.

| 플랫폼 | 방식 | 설정 |
|---|---|---|
| Linux | systemd user service | 실패하면 다시 시작합니다. `MemoryMax`로 메모리 상한을 겁니다. |
| macOS | launchd | 실패하면 다시 시작합니다. |

## 배포

GitHub Releases에 플랫폼별 실행 파일, Plugin `.js`, SHA-256 체크섬을 올립니다. 지원 플랫폼은 [Tech Stack](001.TECH_STACK.md#지원-플랫폼과-배포)을 참고하세요.

## 설정

설정 파일은 TOML이며 `Bun.TOML.parse`로 읽습니다. 실행 파일의 `--config`로 지정하며, 지정하지 않으면 `$XDG_CONFIG_HOME/agentoscope/config.toml`을 읽습니다. `XDG_CONFIG_HOME`이 없거나 절대 경로가 아니면 `~/.config`를 씁니다. 기본 위치에 파일이 없으면 모든 항목에 기본값을 쓰고, `--config`로 지정한 파일이 없거나 모르는 키가 있으면 시작하지 않습니다. Main Server의 항목은 [Data Storage](008.DATA_STORAGE.md#설정)를, Visualization의 항목(`[visualization]` 표)은 [Visualization 구현](011.VISUALIZATION.md#접속)을 참고하세요.

[Client Adapter Daemon의 설정](../001.model/006.CLIENT_ADAPTER_DAEMON.md#설정)에 더해 상태 디렉터리와 Plugin 디렉터리를 둡니다. 모든 항목은 설정 파일의 `[daemon]` 표에 둡니다.

| 항목 | 키 | 기본값 | 설명 |
|---|---|---|---|
| 상태 디렉터리 | `state_directory` | `$AGENTOSCOPE_HOME/agentoscope/daemon` | Daemon이 쓰는 파일(로그, 잠금 파일, Plugin의 상태)을 두는 디렉터리입니다. 없으면 권한 `0700`으로 만듭니다. |
| Plugin 디렉터리 | `plugin_directory` | `$AGENTOSCOPE_HOME/agentoscope/plugins` | 빌드한 Plugin을 두는 디렉터리입니다. Daemon은 시작할 때 여기 있는 Plugin을 모두 불러와 Plugin Collection에 등록하고, 그 가운데 "사용할 Plugin"을 시작합니다([Plugin Guide](004.PLUGIN_GUIDE.md#daemon이-plugin을-불러오는-방식) 참고). 디렉터리가 없으면 로그를 남기고 Plugin 없이 실행합니다. |
| 사용할 Plugin | `plugins` | Plugin 디렉터리에 있는 모든 Plugin | 시작할 Plugin의 에이전트 id 목록입니다(예: `["opencode"]`). |
| Transport | `transport` | `"in-process"` | 지금은 [프로세스 내 호출](003.TRANSPORT.md#프로세스-내-호출)만 구현했습니다. 다른 Transport를 구현하면 이 키에 종류를, 따로 둘 키에 주소(표준입출력이면 실행할 Main Server 명령)를 둡니다. Transport별 주소는 [Transport](003.TRANSPORT.md#transport-바인딩)를 참고하세요. |
| Ack 타임아웃 | `ack_timeout_ms` | `30000` | 밀리초입니다. Main Server의 `busy_timeout_ms`([Data Storage](008.DATA_STORAGE.md#설정))보다 길어야 하며, 그렇지 않으면 시작하지 않습니다. |
| 재시도 횟수 | `retry_count` | `5` | 재시도 가능한 실패 뒤 같은 Transport Unit을 다시 보내는 횟수입니다. 첫 전송은 세지 않으며, `0`이면 다시 보내지 않습니다. |
| 재시도 간격 | `retry_interval_ms` | `1000` | 첫 재시도 전에 기다리는 시간(밀리초)입니다. 재시도할 때마다 두 배로 늘리며, 60초를 넘지 않습니다. |

`AGENTOSCOPE_HOME`은 [Data Storage](008.DATA_STORAGE.md#설정)와 같으며, 없거나 절대 경로가 아니면 `~/.local/share`입니다. 상대 경로는 설정 파일이 있는 디렉터리를 기준으로 합니다.

## 시작과 종료

한 프로세스 안에서 다음 순서로 시작하고 종료합니다.

1. Main Server를 열고 파생 데이터를 준비합니다. 준비하는 동안 Main Server는 Transport Unit을 `unavailable`로 거절하므로, Daemon은 준비가 끝난 뒤에 시작합니다.
2. Daemon이 상태 디렉터리에 잠금 파일 `daemon.lock`을 만들고 자신의 PID를 씁니다. 잠금 파일이 있고 그 PID의 프로세스가 실행 중이면 시작하지 않고 종료 코드 `1`로 끝납니다. 프로세스가 없으면 비정상 종료로 남은 잠금 파일로 보고 다시 만듭니다.
3. Plugin을 불러와 등록하고, "사용할 Plugin"마다 상태 디렉터리 아래의 `plugins/<에이전트 id>/`를 만들어 [`PluginContext`](005.PLUGIN_INTERFACE.md#plugincontext)로 넘기며 `start`를 부릅니다.
4. Visualization을 시작하고 상태 디렉터리에 접속 정보 파일 `visualization.json`을 씁니다([Visualization 구현](011.VISUALIZATION.md#접속-정보-파일과-토큰) 참고). 시작하지 못하면 로그를 남기고 Visualization 없이 실행합니다.
5. `SIGINT`나 `SIGTERM`을 받으면 Visualization을 멈추고 접속 정보 파일을 지웁니다.
6. Plugin마다 `stop`을 부르고 최대 10초 기다립니다.
7. 전송 대기열에 남은 Transport Unit을 최대 10초 동안 보냅니다. 그 안에 보내지 못한 Transport Unit은 로그를 남기고 버립니다.
8. 잠금 파일을 지우고 Main Server를 닫습니다.

- 처리하지 못한 `Promise` 거절은 로그만 남기고 프로세스를 끝내지 않습니다. Plugin 안의 오류로 Daemon과 Main Server가 멈추지 않게 하기 위해서입니다([Plugin Interface](005.PLUGIN_INTERFACE.md#시작과-종료) 참고).
- 전송 대기열은 메모리에만 있습니다. 재시도를 모두 실패한 Transport Unit처럼, 프로세스가 끝날 때 남은 Transport Unit도 다시 보내지 않습니다.

## 로그

Daemon은 상태 디렉터리의 `daemon.log`에 한 줄에 JSON 하나로 기록합니다. 파일은 권한 `0600`으로 만듭니다. Plugin이 [`logger`](005.PLUGIN_INTERFACE.md#logger)로 남긴 로그에는 `details.agent`에 그 Plugin의 에이전트 id를 붙입니다. Main Server의 로그는 표준 오류에 씁니다.

## 결정되지 않은 사항

- `MemoryMax`의 값. 구현한 뒤 측정한 메모리로 정합니다. Linux x64에서 데이터가 거의 없을 때 OpenCode Plugin을 켜고 실행한 RSS는 약 42 MB였습니다.
- 서비스 등록 명령. 아직 구현하지 않았습니다.
- 로그 파일의 크기 상한과 교체
