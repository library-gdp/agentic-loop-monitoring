# 001.TECH_STACK.md

이 문서는 시스템의 각 구성 요소를 구현하는 기술 스택을 정합니다. 구성 요소는 [System Architecture](../001.model/001.SYSTEM_ARCHITECTURE.md)를, 용어는 [Glossary](../001.model/002.GLOSSARY.md)를 따릅니다.

기술 스택을 고르는 첫 번째 기준은 메모리 사용량입니다. 이 애플리케이션을 쓰려는 환경에서 가장 부족한 자원이 메모리이기 때문입니다.

## 구현 언어

| 구성 요소 | 구현 언어 | 이유 |
|---|---|---|
| Client Adapter Daemon, Plugin | TypeScript | [Implement the Client Adapter Daemon and Plugins in TypeScript](../../adr/2026-10-22-implement-daemon-and-plugins-in-typescript.md)를 참고하세요. |
| Main Server | TypeScript | Daemon과 한 프로세스로 구동해 메모리를 줄이고, Session Log Event, Transport Unit, Ack의 타입 정의 하나를 함께 쓰기 위해서입니다. [Run the Client Adapter Daemon and the Main Server in one Bun process](../../adr/2026-10-29-run-daemon-and-main-server-in-one-bun-process.md)를 참고하세요. |

## 런타임과 프레임워크

| 항목 | 선택 | 이유 |
|---|---|---|
| 런타임 | Bun | 대기 상태의 메모리가 Node.js, Deno보다 적고, `bun build --compile`로 실행 파일 하나를 만들 수 있습니다. |
| HTTP 프레임워크 | Hono | 의존성이 없는 경량 프레임워크이며 Web 표준 API 위에서 동작해 `Bun.serve`에 그대로 붙습니다. Visualization과 HTTP를 쓰는 Transport(REST API, Streamable HTTP, WebSocket)에 씁니다. |

결정 배경은 [Run the Client Adapter Daemon and the Main Server in one Bun process](../../adr/2026-10-29-run-daemon-and-main-server-in-one-bun-process.md)를 참고하세요.

## 실행 구성

Daemon과 Main Server를 하나의 프로세스로 구동합니다. 실행 파일은 하나이며, Daemon과 Main Server가 들어 있습니다. Plugin은 따로 빌드해 Plugin 디렉터리에 두고, Daemon이 시작할 때 같은 프로세스로 불러옵니다([Plugin Guide](004.PLUGIN_GUIDE.md#plugin을-daemon에-넣는-방식) 참고).

- Daemon과 Main Server 사이의 Transport는 [프로세스 내 호출](003.TRANSPORT.md#프로세스-내-호출)입니다. Transport Unit을 직렬화하지 않고 객체 그대로 넘깁니다.
- Daemon은 Main Server를 Transport로만 부르며, Main Server의 Core나 Persistence를 직접 부르지 않습니다.
- Daemon이 사용자 계정마다 하나씩 상주하므로([Client Adapter Daemon 구현](007.CLIENT_ADAPTER_DAEMON.md#실행)), Main Server와 그 데이터 파일도 사용자 계정마다 하나입니다.

## 코드 저장소와 빌드

이후의 항목은 모두 [Choose the implementation tooling and Visualization stack](../../adr/2026-10-30-choose-the-implementation-tooling-and-visualization-stack.md)에서 정했습니다.

| 항목 | 선택 | 이유 |
|---|---|---|
| 코드 저장소 | 단일 저장소, Bun workspaces | 공유 타입을 한 곳에 두고, 패키지 의존 관계로 모듈 경계를 강제합니다. Plugin 패키지도 같은 저장소에 둡니다. 구성은 아래 [패키지](#패키지)를 참고하세요. |
| Bun 버전 | 1.4.4 이상, CI와 개발 환경에서 고정 | 측정과 시제품에 쓴 버전입니다. |
| Plugin 번들 | `bun build --target=bun --format=esm` | Plugin 하나를 ES 모듈 파일 하나로 만듭니다. 번들 도구를 더하지 않습니다. |
| 실행 파일 빌드 | `bun build --compile --no-compile-autoload-dotenv --no-compile-autoload-bunfig` | 기본값이면 실행한 디렉터리의 `.env`와 `bunfig.toml`을 읽습니다. |

### 패키지

| 패키지(`packages/`) | 내용 | 의존하는 패키지 |
|---|---|---|
| `plugin-api` | Plugin 인터페이스와 Session Log Event 타입 | 없음 |
| `protocol` | Transport Unit, Ack 타입 | `plugin-api` |
| `core` | Core 모듈. Activity Model 구성, Ingest API, Query API, Repository API | `protocol` |
| `persistence` | Persistence 모듈. Repository API의 SQLite 구현 | `core` |
| `input-adapter` | Input Adapter 모듈. Decoder, 프로세스 내 호출, REST API | `core`, `protocol` |
| `visualization` | Visualization 모듈. Hono 라우트와 Preact SPA(`web/`) | `core` |
| `daemon` | Client Adapter Daemon | `plugin-api`, `protocol` |
| `plugin-opencode` | OpenCode Plugin | `plugin-api` |
| `app` | 실행 파일 `alm`. 위 패키지를 조립합니다. | `core`, `daemon`, `input-adapter`, `persistence`, `visualization` |

## 라이브러리

| 항목 | 선택 | 이유 |
|---|---|---|
| 입력 검증 | Valibot | Input Adapter의 Decoder와 Plugin의 레코드 검증에 씁니다. 측정한 메모리가 Zod보다 약 7 MB 적고, Plugin마다 따로 번들되므로 이 차이가 중요합니다. 모르는 필드를 보존해야 하는 객체에는 `looseObject`를 씁니다. |
| DB 접근 | `bun:sqlite`와 직접 쓴 SQL | DDL, 트랜잭션, 질의가 이미 SQL로 문서화되어 있습니다. ORM과 쿼리 빌더를 쓰지 않습니다. |
| 파일 감시 | `node:fs`의 `watch`와 주기적 재검사 | Bun에 내장되어 있습니다. 재검사는 놓친 이벤트를 보완합니다. |
| 설정 파일 | TOML, `Bun.TOML.parse` | Bun에 내장된 파서로 읽어 의존성이 없습니다. |

## Visualization

| 항목 | 선택 | 이유 |
|---|---|---|
| 클라이언트 | Preact 기반 SPA | 서버 렌더링은 큰 문자열을 수집과 같은 이벤트 루프에서 만듭니다. SPA는 렌더링을 브라우저로 넘깁니다. |

| 스타일, 차트 | 일반 CSS, SVG 직접 구현 | 필요한 화면이 아직 정해지지 않았으므로 무거운 차트나 에디터를 미리 넣지 않습니다. |

구성과 접속 방식은 [Visualization](010.VISUALIZATION.md)을 참고하세요.

## 아직 정하지 않는 것

- 원격 Transport의 인증과 암호화: 팀 단계에서 정합니다. 그때는 Daemon별 Bearer 토큰과 Caddy 같은 프록시의 TLS를 먼저 검토합니다.
- `event.body` 압축: 되풀이되는 input의 중복 제거와 함께 정합니다([Data Storage](008.DATA_STORAGE.md#결정되지-않은-사항) 참고).
- 질의를 Worker로 분리하는 것: 질의가 수집을 막는 것이 측정될 때 정합니다.
