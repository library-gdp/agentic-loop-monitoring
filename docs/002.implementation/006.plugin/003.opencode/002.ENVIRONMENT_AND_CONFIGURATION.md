# 002.ENVIRONMENT_AND_CONFIGURATION.md

이 문서는 OpenCode의 환경 변수와 설정 파일을 정리하고, 그중 OpenCode Plugin의 수집에 영향을 주는 것을 밝힙니다. Plugin의 구현 방안은 [OpenCode Plugin](001.OVERVIEW.md)을, 용어는 [Glossary](../../../001.model/002.GLOSSARY.md)를 따릅니다.

## 대상 버전과 출처

[OpenCode Plugin](001.OVERVIEW.md#대상-버전)과 같이 OpenCode 1.19.x를 대상으로 합니다. 아래 내용은 v1.19.5 소스와 같은 태그의 공식 문서(`packages/web/src/content/docs/cli.mdx`, `config.mdx`)에서 확인했습니다. 공식 문서와 소스가 다르면 소스를 따르고 차이를 적었습니다.

| 소스 위치 | 내용 |
|---|---|
| `packages/core/src/flag/flag.ts` | 대부분의 환경 변수 |
| `packages/opencode/src/effect/runtime-flags.ts` | 기능을 켜고 끄는 환경 변수 |
| `packages/core/src/global.ts` | 데이터, 설정, 캐시, 상태 디렉터리 |
| `packages/core/src/database/database.ts` | DB 경로 |
| `packages/opencode/src/config/config.ts` | 설정 파일을 읽는 순서와 합치는 방식 |
| `packages/core/src/v1/config/config.ts` | 설정 파일의 스키마 |

## 수집에 영향을 주는 항목

Plugin은 OpenCode 프로세스의 환경 변수와 설정을 알 수 없습니다. 아래 항목이 기본값이 아니면 Plugin이 DB를 찾지 못하거나, 기록되는 내용이 달라집니다. 각 항목의 자세한 내용은 뒤의 절을 참고하세요.

| 항목 | 영향 |
|---|---|
| `XDG_DATA_HOME`, `OPENCODE_DB`, `OPENCODE_DISABLE_CHANNEL_DB`, 빌드 채널 | DB 위치가 바뀝니다. Plugin은 기본 위치만 찾으므로 다른 위치의 DB는 수집하지 못합니다. `OPENCODE_DB`가 `:memory:`이면 DB 파일이 없습니다. |
| `compaction.auto`, `OPENCODE_DISABLE_AUTOCOMPACT` | 자동 Compaction이 일어나는지 정합니다. 끄면 사용자가 직접 요청할 때만 Compaction이 기록됩니다. |
| `compaction.prune`, `OPENCODE_DISABLE_PRUNE` | 켜면 오래된 tool part에 `state.time.compacted`를 넣어 다시 기록합니다. 같은 part의 `completed` 행이 하나 더 생깁니다. |
| `compaction.tail_turns`, `compaction.preserve_recent_tokens`, `compaction.reserved` | Compaction 뒤 LLM Call의 input에 원문으로 남는 범위가 달라집니다. |
| `tool_output.max_lines`, `tool_output.max_bytes` | 이 한도를 넘는 tool 출력은 DB에 미리보기만 남고 전체는 `tool-output/` 디렉터리에 파일로 저장됩니다. 그 파일은 7일 뒤 지워집니다. |
| `subagent_depth` | Subagent가 Subagent를 띄울 수 있는 깊이입니다. 기본값 `1`에서는 Subagent가 Subagent를 띄우지 않습니다. |
| `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS` | 백그라운드 Subagent를 켭니다. 기록 형식에 주는 영향은 확인하지 않았습니다. |
| `OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX` | LLM 응답의 최대 output token을 바꿉니다. |

### 환경 변수를 넘기는 프로세스

OpenCode는 시작할 때 자기 프로세스에 `AGENT=1`, `OPENCODE=1`, `OPENCODE_PID=<pid>`를 설정합니다. bash tool 등 OpenCode가 띄운 자식 프로세스는 이 값을 물려받습니다.

## 디렉터리

OpenCode는 [XDG Base Directory](https://specifications.freedesktop.org/basedir-spec/latest/)를 따르며, 각 디렉터리 아래에 `opencode` 디렉터리를 만듭니다. OpenCode 전용 환경 변수로 이 디렉터리들을 바꿀 수는 없습니다.

| 디렉터리 | 환경 변수 | 기본 위치(Linux) | 담는 것 |
|---|---|---|---|
| 데이터 | `XDG_DATA_HOME` | `~/.local/share/opencode` | DB, `auth.json`, `log/`, `snapshot/`, `tool-output/`, `repos/` |
| 설정 | `XDG_CONFIG_HOME` | `~/.config/opencode` | 전역 설정 파일, `agents/`, `commands/`, `plugins/` 등 |
| 캐시 | `XDG_CACHE_HOME` | `~/.cache/opencode` | 내려받은 실행 파일(`bin/`) 등 |
| 상태 | `XDG_STATE_HOME` | `~/.local/state/opencode` | 잠금 파일 등 |
| 임시 | - | `<OS 임시 디렉터리>/opencode` | 임시 파일 |

### DB 경로

| 조건 | 경로 |
|---|---|
| `OPENCODE_DB`가 `:memory:`이거나 절대 경로 | 그 값 |
| `OPENCODE_DB`가 상대 경로 | `<데이터 디렉터리>/<OPENCODE_DB>` |
| 채널이 `latest`, `beta`, `prod`이거나 `OPENCODE_DISABLE_CHANNEL_DB`가 `1`, `true` | `<데이터 디렉터리>/opencode.db` |
| 그 밖의 채널 | `<데이터 디렉터리>/opencode-<채널>.db`. 채널 이름에서 `[a-zA-Z0-9._-]`가 아닌 문자는 `-`로 바꿉니다. |

채널은 환경 변수가 아니라 빌드할 때 넣는 상수(`OPENCODE_CHANNEL`)이며, 정식 배포본은 `latest`입니다. 소스에서 직접 실행하면 채널이 `local`이므로 `opencode-local.db`를 씁니다. `opencode db path`로 실제 경로를 확인할 수 있습니다.

### 로그

OpenCode 자신의 실행 로그는 `<데이터 디렉터리>/log/opencode.log`에 남습니다. Session Log가 아니므로 Plugin이 수집하지 않습니다.

## 환경 변수

`boolean` 값은 `1` 또는 `true`(대소문자 무시)일 때 켜집니다. "실험 기능 포함"은 값을 주지 않았을 때 `OPENCODE_EXPERIMENTAL`의 값을 따른다는 뜻입니다.

### 경로와 설정

| 변수 | 타입 | 설명 |
|---|---|---|
| `OPENCODE_DB` | string | DB 경로. [DB 경로](#db-경로) 참고 |

### 환경 변수가 아닌 것

다음 이름은 빌드할 때 넣는 상수이므로 실행할 때 환경 변수로 바꿀 수 없습니다: `OPENCODE_CHANNEL`, `OPENCODE_VERSION`, `OPENCODE_LIBC`, `OPENCODE_MODELS_DEV`. 이 밖에 `OPENCODE_TEST_*`는 시험용입니다.

## 설정 파일

설정 파일은 JSON 또는 JSONC입니다. 여러 곳의 설정을 차례로 읽어 합치며, 같은 키는 나중에 읽은 값이 이깁니다. 겹치지 않는 키는 모두 남습니다.

### 읽는 순서

| 순서 | 출처 | 위치 |
|---|---|---|
| 1 | 원격 설정 | 인증한 제공자의 `<url>/.well-known/opencode` |
| 2 | 전역 설정 | `<설정 디렉터리>/config.json`, `opencode.json`, `opencode.jsonc` 순서 |
| 3 | `OPENCODE_CONFIG` | 그 경로의 파일 |
| 4 | 프로젝트 설정 | 현재 디렉터리부터 Git worktree 루트까지 올라가며 찾은 `opencode.json(c)`. `OPENCODE_DISABLE_PROJECT_CONFIG`이면 건너뜁니다. |
| 5 | `.opencode` 디렉터리와 `OPENCODE_CONFIG_DIR` | 각 디렉터리의 `opencode.json(c)`와 agents, commands, modes, plugins |
| 6 | `OPENCODE_CONFIG_CONTENT` | 환경 변수의 JSON |
| 7 | 계정 조직 설정 | 로그인한 OpenCode 계정의 조직 설정 |
| 8 | 관리 설정 파일 | Linux `/etc/opencode/`, macOS `/Library/Application Support/opencode/`, Windows `%ProgramData%\opencode`의 `opencode.json(c)` |
| 9 | macOS 관리 환경설정 | MDM으로 배포한 `ai.opencode.managed` plist. 사용자가 덮어쓸 수 없습니다. |

모두 합친 뒤 `OPENCODE_PERMISSION`을 `permission`에 합치고, `OPENCODE_DISABLE_AUTOCOMPACT`와 `OPENCODE_DISABLE_PRUNE`을 `compaction`에 적용합니다. `autoshare: true`이고 `share`가 없으면 `share`를 `auto`로 둡니다.

TUI 설정은 별도 파일(`tui.json`)이며 `OPENCODE_TUI_CONFIG`로 바꿀 수 있습니다.

### 값 치환

설정 파일 안에서 `{env:이름}`은 환경 변수 값으로(없으면 빈 문자열), `{file:경로}`는 파일 내용으로 바뀝니다.

### 최상위 키

| 키 | 설명 |
|---|---|
| `$schema` | 스키마 URL(`https://opencode.ai/config.json`) |
| `model`, `small_model` | 기본 모델과 제목 생성 같은 가벼운 작업에 쓸 모델(`provider/model`) |
| `provider`, `enabled_providers`, `disabled_providers` | 제공자 설정과 허용, 차단 목록. 둘 다에 있으면 차단합니다. |
| `agent`, `mode`, `default_agent` | Agent 정의와 기본 primary Agent. `mode`는 primary Agent로 바뀌어 `agent`에 합쳐집니다. |
| `subagent_depth` | Subagent가 다른 Subagent를 띄울 수 있는 깊이. 기본값 `1`, `0`이면 Subagent를 띄우지 않습니다. |
| `command` | 사용자 명령 |
| `skills` | 추가 skill 디렉터리 |
| `instructions` | 추가로 읽을 지시 파일 |
| `permission`, `tools` | tool 권한과 tool 켜고 끄기 |
| `mcp` | MCP 서버 |
| `plugin` | OpenCode Plugin(npm 패키지 또는 파일) |
| `lsp`, `formatter` | LSP 서버와 formatter |
| `compaction` | `auto`(기본 `true`), `prune`(기본 `false`), `tail_turns`, `preserve_recent_tokens`, `reserved` |
| `tool_output` | `max_lines`(기본 2000), `max_bytes`(기본 51200). 넘으면 전체를 `tool-output/`에 저장하고 미리보기만 돌려줍니다. |
| `snapshot` | 파일 변경 추적용 스냅숏. 기본값은 켜짐입니다. |
| `share`, `autoshare` | Session 공유 방식(`manual`, `auto`, `disabled`). `autoshare`는 예전 키입니다. |
| `autoupdate` | 업데이트 확인(`true`, `false`, `"notify"`) |
| `server` | `serve`, `web`의 서버 설정 |
| `shell` | 터미널과 bash tool의 기본 shell |
| `watcher` | 파일 감시에서 제외할 glob |
| `attachment` | 이미지 첨부의 크기 한도와 크기 조정 |
| `username` | 표시할 사용자 이름. 없으면 OS 사용자 이름 |
| `references`, `reference` | reference 설정 |
| `enterprise` | Enterprise URL |
| `experimental` | `batch_tool`, `openTelemetry`, `primary_tools`, `continue_loop_on_deny`, `mcp_timeout`, `policies`, `disable_paste_summary` |
| `layout` | 사용하지 않습니다(deprecated). |

## 결정되지 않은 사항

- Plugin이 기본 위치가 아닌 DB를 받을 설정의 형식([OpenCode Plugin](001.OVERVIEW.md#결정되지-않은-사항)의 같은 항목)
- prune이 남기는 두 번째 `completed` 행을 어떻게 다룰지. 실제 DB에서 이 행을 확인하지 않았습니다.
- `tool-output/`에 저장된 전체 tool 출력을 수집할지
- `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS`를 켰을 때 child session의 기록이 달라지는지
