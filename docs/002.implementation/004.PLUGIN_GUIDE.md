# 004.PLUGIN_GUIDE.md

이 문서는 [Plugin Specification](../001.model/005.PLUGIN_SPEC.md)을 따르는 Plugin을 구현하는 방안을 정합니다. Plugin의 역할과 규칙은 model 문서를 따르며, 이 문서는 바꾸지 않습니다. 구현 언어는 [Tech Stack](001.TECH_STACK.md)을, 용어는 [Glossary](../001.model/002.GLOSSARY.md)를 따릅니다.

## Plugin을 Daemon에 넣는 방식

Daemon은 어떤 Plugin이 있는지 모릅니다. Daemon 소스와 실행 파일에는 Plugin 코드도, Plugin 목록도 없습니다. Plugin은 Daemon과 따로 빌드합니다. 빌드한 Plugin을 Plugin 디렉터리에 넣으면, Daemon은 시작할 때 이를 불러오고 각 Plugin이 Daemon의 Plugin Collection에 자신을 등록합니다. Daemon은 에이전트의 Session Log를 수집할 Plugin을 이 Collection에서 에이전트 id로 골라 씁니다. 새 에이전트를 지원하거나 Plugin을 고칠 때 Daemon을 다시 빌드하지 않습니다. 결정 배경은 [Load built Plugins into the Daemon at runtime](../../adr/2026-10-29-load-built-plugins-into-daemon-at-runtime.md)을 참고하세요.

### 패키지 구성

| 패키지 | 내용 | 의존하는 패키지 |
|---|---|---|
| `@alm/plugin-api` | [Plugin Interface](005.PLUGIN_INTERFACE.md)의 타입과 `PLUGIN_API_VERSION` | 없음 |
| `@alm/plugin-<에이전트 이름>` | 에이전트 하나의 Plugin 구현. 에이전트마다 하나씩 둡니다. | `@alm/plugin-api` |
| `@alm/daemon` | Plugin 불러오기와 Plugin Collection, Transport Unit 전송, Transport Client | `@alm/plugin-api`, `@alm/protocol` |

- 패키지는 모두 단일 저장소의 `packages/`에 두고 Bun workspaces로 나눕니다([Tech Stack](001.TECH_STACK.md#코드-저장소와-빌드) 참고).
- Daemon과 Plugin은 Plugin API에만 의존합니다. Daemon은 Plugin 패키지에, Plugin은 Daemon 패키지나 다른 Plugin 패키지에 의존하지 않습니다.
- Plugin API에서 실행 중에 쓰는 값은 `PLUGIN_API_VERSION` 하나뿐이며, Plugin을 빌드할 때 Plugin 안에 함께 들어갑니다. 그래서 Daemon은 Plugin에 모듈을 제공하지 않습니다.

### 빌드한 Plugin

빌드한 Plugin은 [Plugin 모듈](005.PLUGIN_INTERFACE.md#plugin-모듈)을 담은 ES 모듈 파일 하나입니다. Plugin이 쓰는 라이브러리는 모두 이 파일 안에 넣으며, 파일 밖에서는 Daemon 런타임의 내장 모듈만 가져옵니다. 파일 이름은 에이전트 id를 씁니다. 번들은 `bun build --target=bun --format=esm`으로 합니다.

```
<Plugin 디렉터리>/
├── claude-code.js
├── codex.js
└── opencode.js
```

### Daemon이 Plugin을 불러오는 방식

Daemon은 시작할 때 다음을 수행합니다.

1. **불러오기**: Plugin 디렉터리 바로 아래의 `.js` 파일을 파일 이름 순서대로 동적 `import()`로 불러옵니다.
2. **등록**: 불러온 모듈마다 `apiVersion`이 Daemon이 빌드에 쓴 `PLUGIN_API_VERSION`과 같은지 확인하고, 같으면 `register`를 불러 [`PluginRegistry`](005.PLUGIN_INTERFACE.md#pluginregistry)를 넘깁니다. Plugin은 이때 자신을 Plugin Collection에 등록합니다. 모든 모듈을 처리하면 등록을 닫습니다.
3. **고르기와 시작**: 설정의 "사용할 Plugin"에 있는 에이전트 id마다 Plugin Collection에서 그 `agent`의 Plugin을 골라 `start`를 부릅니다. 이 Plugin이 넘긴 Transport Unit의 `source.agent`와 `source.plugin_version`은 Plugin의 `agent`와 `version`으로 채웁니다.

- 어느 단계에서든 실패하면 Daemon은 로그를 남기고 그 모듈이나 Plugin을 건너뜁니다. 다른 Plugin은 그대로 등록하고 시작하며, Daemon은 계속 실행합니다.
- "사용할 Plugin"에 있는 에이전트 id의 Plugin이 Collection에 없으면 로그를 남깁니다.
- Plugin 디렉터리의 모듈은 활성화 여부와 관계없이 모두 불러오고 등록합니다. 그래서 모듈을 불러오거나 `register`를 부르는 것만으로는 아무 일도 하지 않아야 합니다([Plugin 모듈](005.PLUGIN_INTERFACE.md#plugin-모듈) 참고).
- Plugin을 시작한 뒤 언제, 어떤 Session Log를 수집할지는 Plugin의 Trigger와 수집 방식을 따릅니다.

### Plugin 추가하기

1. 에이전트의 Plugin 패키지를 만들고, Plugin API에 맞춰 구현합니다.
2. Plugin을 ES 모듈 파일 하나로 빌드합니다.
3. 그 파일을 Plugin 디렉터리에 넣습니다. Plugin을 고칠 때는 파일을 바꿉니다.
4. 설정의 "사용할 Plugin"에 에이전트 id를 넣습니다.
5. Daemon을 다시 시작합니다.
6. [에이전트별 문서](#에이전트별-문서)를 추가합니다.

[Plugin Interface](005.PLUGIN_INTERFACE.md)의 예시에 쓴 패키지 이름 `plugin-api`는 `@alm/plugin-api`입니다.

## Session Log를 파일로 수집하는 경우

에이전트가 Session Log를 파일로 기록하고 Plugin이 그 파일을 읽어 수집할 때는 다음을 따릅니다. 이 내용은 [Plugin Specification](../001.model/005.PLUGIN_SPEC.md)의 규칙을 파일에 적용한 것입니다.

- **Trigger**: 파일 변경 감시를 Trigger로 쓸 수 있습니다. 감시는 `node:fs`의 `watch`로 하고, 놓친 이벤트를 보완하기 위해 주기적으로 다시 검사합니다. 간격은 [에이전트별 문서](#에이전트별-문서)에서 정합니다.
- **수집 방식**: 에이전트별 문서에 파일의 위치와, 그 파일이 어느 Session의 것인지 알아내는 방법을 적습니다. 파일이 다른 파일로 교체되거나, 잘리거나, 삭제되었을 때의 처리도 정합니다. 에이전트가 계속 쓰는 동안 파일 끝을 끝없이 따라가지 않도록 한 번에 읽는 범위를 정합니다.
- **완결되지 않은 레코드**: 레코드가 아직 다 기록되지 않았는지는 형식에 맞춰 판단합니다. 예를 들어 줄 단위 형식에서 마지막 줄이 줄바꿈으로 끝나지 않으면 그 레코드는 아직 기록 중입니다.
- **event id**: 에이전트가 레코드마다 고유 id를 기록하지 않으면, 파일 안에서 레코드의 위치로 event id를 만듭니다.
- **메모리**: 레코드를 하나씩 읽어 변환하고 곧바로 Transport Unit으로 넘깁니다. Turn의 레코드나 Session Log Event를 메모리에 모아 두지 않으며, 진행 중인 Turn에 대해서는 `turn.id`와 다음 Turn 안 위치만 기억합니다. 이 두 값은 수집한 위치와 함께 저장해, 다시 시작해도 Turn의 시작부터 다시 읽지 않고 이어 수집합니다.

## 결정되지 않은 사항

- 빌드한 Plugin을 Plugin 디렉터리에 설치하는 절차. Plugin `.js`와 SHA-256 체크섬은 GitHub Releases에 올립니다([Tech Stack](001.TECH_STACK.md#지원-플랫폼과-배포) 참고).
- Plugin 디렉터리의 Plugin을 믿을 수 있는지 확인하는 방법(예: 서명 검증). 오픈소스 단계에서 정합니다.
- Daemon을 다시 시작하지 않고 Plugin을 추가하거나 바꾸는 방법
